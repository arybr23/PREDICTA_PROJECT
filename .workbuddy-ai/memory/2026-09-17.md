# Session 3 — Account Profile wired (all four pages now live)

## BE
- `config/firm.js` (new) — default firm/account/stores, plus `initialStock()`.
  Stock seeds at a deterministic 0.4–9 days of cover per ingredient so the
  short/low/ok spread is realistic rather than uniformly green.
- `config/catalog.js` — added `dailyIngredientRequirement()`: typical daily
  ingredient burn derived from `baseDemand × recipe qty`.
- `services/store.js` — added `stock` to state + `getStock` / `setStockLevel`.
  The seed is deterministic, so it only needs persisting once edited.
- `routes/account.js` (new) — `/profile`, `/stores`, `/stock` (GET + PATCH).

**Key design point:** `GET /account/stock` compares on-hand against
**tomorrow's forecast requirement** (reusing the cached `predict.py` output), so
the page answers "what do I need to buy?" instead of just listing quantities.
Each row gets `short` / `low` / `ok` plus `days_of_cover` and `shortfall`.
If the forecast fails the endpoint still returns stock, with
`forecast_error` set — the UI degrades to on-hand-only.

## FE
- `AccountProfile.jsx` + `ProfileCard` / `StoreList` / `StockManagement` all
  wired. Stock rows have an inline editable `on_hand` (commits on blur/Enter).

## Verified
- `/account/*` endpoints pass, including 400s for missing fields and negative
  quantities, and 404 for an unknown ingredient row.
- Live spread was 5 short / 4 low / 25 ok across 34 ingredients.
- All four pages server-render; 0 lint warnings, build passes.
- Store reset afterwards so the stock edit didn't linger.

## Remaining gaps (now documented in README)
- **No auth.** `/account/profile` serves one hardcoded account; `Accounts` has
  an unused `passwordHash`. No per-user scoping.
- Weather not forecast; `recharts` unused at root.
